# SupplySense Nexus - Project Instructions

## Project Purpose

SupplySense Nexus is an AI-powered supply chain resilience and decision intelligence platform. It helps supply-chain teams understand demand, inventory, suppliers, procurement, disruptions, and operational trade-offs. Its central differentiator is **disruption-aware procurement decision intelligence**.

## Approved Stack

- **FastAPI** - Web framework
- **Pydantic** - Data validation
- **SQLAlchemy** - ORM

- **psycopg2-binary** - PostgreSQL adapter

### Deployment
- **Docker** - Containerization (when available)

## Coding Conventions

1. **Use type hints** on all function signatures.
2. **Follow PEP 8** style guidelines.
3. **Use Pydantic models** for all request and response schemas.
4. **Use SQLAlchemy** for all database operations; never write raw SQL.
5. **Use async/await** for all database and I/O operations.
6. **Use descriptive variable names**; avoid abbreviations.
7. **Keep functions small and focused** (single responsibility).
8. **Write docstrings** for all public functions and classes.
9. **Use Python 3.12+ features** where appropriate.
10. **Import order**: standard library, third-party, local (isort style).

## Security Rules

1. **Never commit secrets** to version control. Use `.env` files (gitignored).
2. **Never write raw SQL** in application code. Use SQLAlchemy ORM.
3. **Never expose API keys** in frontend code.
4. **Always validate input** using Pydantic schemas.
5. **Always use parameterized queries** (enforced by SQLAlchemy).
6. **Implement authentication** on all mutating endpoints.
7. **Implement authorization** to restrict data access by organization.
8. **Hash passwords** using bcrypt or equivalent.
9. **Sanitize all user inputs** to prevent injection attacks.
10. **Audit all significant operations** and log to audit trail.

## Data-Labeling Rules

### Mandatory Labels
All data and outputs must carry one of these labels:
- `public` - Publicly available data
- `synthetic` - Generated data mimicking real ERP patterns
- `user-provided` - Data uploaded by users
- `derived` - Computed from other data
- `simulated` - Generated by simulation models

### Labeling Requirements
1. Database tables include a `data_source_label` column.
2. API responses include `data_source_label` in the meta section.
3. Frontend visualizations distinguish actual, forecast, forecasted, and simulated values.
4. Documentation examples use clearly labeled simulated data.
5. **Never present synthetic or simulated data as real data.**
6. All forecast outputs are labeled as "simulated" or "estimated."

### Violation Penalty
- Any code that presents simulated data as real data without labeling is a critical violation.
- Fix immediately and audit the surrounding code.

## Testing Requirements

1. **Write tests** for all new functionality before or concurrently with implementation.
2. **Use pytest** as the test framework.
3. **Target 80%+ line coverage** for core modules.
4. **Run tests** with `pytest` before committing any code.
5. **Use TestClient** from FastAPI for API endpoint testing.
6. **Use isolated test databases** - never test against production data.
7. **All test data must be synthetic** - no real company data in tests.
8. **Test fixtures** should be defined in `conftest.py`.
9. **Test data cleanup** must happen after each test.

### Running Tests
```bash
pytest backend/app/tests/ -v --cov=backend/app
```

## Technology Notes

### Python Version
- Python 3.14.7 is available locally.
- Target Python 3.12+ for compatibility.
- Some features available in 3.14 may not work on 3.12; test accordingly.

### PostgreSQL
- PostgreSQL 17.11 client (`psql`) is available.
- Server is running on port 5432 (verify with `pg_isready`).
- Docker is NOT available on this system.
- Alternative PostgreSQL setup: Install PostgreSQL server locally or use the running instance.
- Connection string: `postgresql://postgres:postgres@localhost:5432/supplysense`

### Docker
- Docker is NOT available on this system.
- Document PostgreSQL setup instructions for non-Docker environments.
- `docker-compose.yml` is provided for when Docker becomes available.

### AI Provider
- No LLM API key is configured by default.
- `OPENAI_API_KEY` in `.env` is required for AI copilot functionality.
- The LLM provider abstraction layer allows swapping providers.
- AI assistant is disabled by default (`ENABLE_AI_ASSISTANT=false`).
