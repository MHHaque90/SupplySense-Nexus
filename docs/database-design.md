# Database Design: SupplySense Nexus

## Overview

PostgreSQL 17 is the primary data foundation. All entities, relationships, and data flows are modeled relationally. The schema is normalized to 3NF with appropriate denormalization for reporting and analytics.

## Data Source Labeling

| Label | Meaning | Examples |
|-------|---------|----------|
| **public** | Publicly available data | Government statistics, open datasets |
| **synthetic** | Generated data mimicking real ERP patterns | Product SKUs, supplier names, order amounts |
| **user-provided** | Data uploaded by users | Company-specific inventory records |
| **derived** | Computed from other data | Days of supply, turnover ratios |
| **simulated** | Generated by simulation models | Disruption impacts, scenario outcomes |

All simulated and synthetic outputs are explicitly labeled in the database and in API responses.

## Data Retention Considerations

- **Demand observations**: Retain indefinitely for model training and backtesting.
- **Inventory snapshots**: Archive after 2 years; keep last 24 months in hot storage.
- **Purchase orders**: Retain for 7 years for financial compliance.
- **Audit events**: Retain indefinitely; append-only.
- **Forecasts**: Retain model version and metrics; archive raw forecast outputs after 1 year.
- **Scenario results**: Retain for project duration plus 1 year.
- **Simulation outputs**: Archive after 6 months; keep metadata indefinitely.
